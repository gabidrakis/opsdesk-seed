## Le pattern M5 (3 pages du module, digérées)
Flux : PR ouverte → GitHub Actions (`pull_request`) → job revue agentique → l'agent lit diff + `CLAUDE.md` → **verdict JSON validé en interne** → **commentaire de PR idempotent** → **l'humain lit, décide, merge**.

**Schéma du verdict (figé)** :
```json
{ "verdict": "approve|request_changes|comment",
  "findings": [ { "severite": "info|attention|bloquant", "fichier": "...", "message": "..." } ],
  "summary": "résumé FR, 2 phrases max" }
```

**4 doctrines non négociables** :
1. L'agent ne merge jamais seul → verrou réel = **branch protection** (Require approvals 1), pas le job CI. `permissions: contents: read`.
2. Sortie structurée validée → JSON non conforme = job échoue, rien n'est publié (JSON.parse + 3 champs, sans schéma externe).
3. Secret hors du code → `ANTHROPIC_API_KEY` en *Actions secret*, jamais dans le YAML (hook M2 `guard-commit.sh` toujours actif).
4. Idempotence → marqueur caché `<!-- opsdesk-revue-agent -->` + upsert (list → find → PATCH/POST), `gh api --paginate --slurp`.

**Durcissement** : court-circuit si diff tout-`.md` (`needed=false`) · diff seul inliné (pas le repo) · `timeout-minutes: 10` · re-run **manuel** tracé (jamais de boucle auto) · Job Summary (PR + commit + verdict + nb findings + durée + horodatage UTC).

**Distinction clé** : « verdict JSON validé » (sortie machine vérifiée, `revue-agent.mjs`) ≠ « commentaire markdown lisible » (rendu humain, `publier-verdict.mjs`).
